# Полный поэтапный план реализации модуля изучения иностранного языка

## 1. Цель и контекст

### 1.1. Цель проекта
Создать программный модуль для стационарного компьютера, который:
- озвучивает учебный текст (TTS),
- распознает речь обучаемого (STT),
- ведет тематические учебные мини-диалоги с ИИ,
- дает корректную и понятную обратную связь по ошибкам,
- отслеживает прогресс обучения,
- доводит обучаемого с нулевого уровня (включая алфавит и базовое
  произношение) до практического уровня для путешествий.

### 1.2. Практический результат обучения (target outcome)
Обучаемый должен уверенно решать базовые задачи за границей:
- аэропорт (регистрация, паспортный контроль, багаж),
- транспорт и навигация,
- заселение в отель,
- ресторан и кафе,
- магазин и покупки,
- аптека и больница,
- экстренные ситуации и полицейский участок,
- краткое бытовое общение.

### 1.3. Основные приоритеты
1. Качество произношения и восприятия речи.
2. Реальные диалоговые сценарии, а не только теория.
3. Удобство для пользователя с нулевым уровнем.
4. Измеримый прогресс и персонализация.
5. Расширяемая архитектура для будущих функций.

---

## 2. Принципы проектирования модуля

1. **Modular by design**: каждый компонент изолирован интерфейсом
   (STT, TTS, LLM, аналитика, контент, прогресс).
2. **Provider-agnostic**: возможность заменить провайдера STT/TTS/LLM
   без переписывания бизнес-логики.
3. **Structured AI output**: ответы ИИ в валидабельном JSON.
4. **Offline/Online strategy**: гибридная модель (лучшее качество при
   наличии сети, безопасный fallback при ее отсутствии).
5. **Pedagogy-first**: учебные сценарии управляют ИИ, а не наоборот.
6. **Observability**: логирование, метрики качества, контроль регрессий.
7. **Incremental delivery**: поэтапный выпуск, где каждый этап
   приносит работоспособную ценность.

## 3. Общая архитектура

### 3.1. Компоненты
1. **Desktop UI Layer**
   - экран урока, запись/воспроизведение, подсветка ошибок,
     прогресс-дашборд.
2. **Audio I/O Layer**
   - захват микрофона, воспроизведение аудио, базовая обработка сигнала.
3. **Speech Layer**
   - STT Adapter: аудио -> текст (+ confidence),
   - TTS Adapter: текст -> озвучка.
4. **AI Dialogue Layer**
   - LLM Gateway,
   - Prompt Builder,
   - Conversation Memory.
5. **Learning Engine**
   - генерация упражнений,
   - оценка ответов,
   - адаптация сложности,
   - план повторений (SRS).
6. **Pronunciation Assessment**
   - оценка произношения по сегментам (слово/звук),
   - рекомендации по коррекции.
7. **Progress & Analytics**
   - журнал попыток, KPI, отчеты по темам и навыкам.
8. **Content Management**
   - словарь, фразы, сценарии, уровни, тематические блоки.

### 3.2. Ключевые потоки
1. TTS-поток: текст урока/реплики ИИ -> аудио.
2. STT-поток: голос пользователя -> транскрипт.
3. Диалоговый поток: реплика пользователя -> ИИ-ответ + фидбек.
4. Оценочный поток: ответ -> анализ ошибок -> обновление прогресса.
5. Адаптивный поток: прогресс -> персонализированное следующее задание.

---

## 4. Педагогическая модель обучения

### 4.1. Уровни
1. **Pre-A0 (с нуля):**
   - алфавит, буквы, звуки, диграфы/сочетания,
   - базовые правила чтения,
   - первичное фонетическое различение.
2. **A0/A1 (базовый выживания):**
   - приветствия, числа, время, простые вопросы/ответы,
   - шаблонные фразы по бытовым ситуациям.
3. **A1+ Travel Ready Minimum:**
   - готовые фразовые блоки для путешествий,
   - короткие диалоги в критически важных сценариях.

### 4.2. Навыки
- Listening (восприятие речи),
- Speaking (произношение + реакция),
- Functional vocabulary (активный минимум),
- Scenario communication (коммуникация по ситуации).

### 4.3. Подходы
1. Comprehensible Input (понятный вход).
2. Active Recall (активное воспроизведение).
3. Spaced Repetition (интервальные повторения).
4. Shadowing (повтор за диктором).
5. Chunk-based learning (фразовые блоки, а не одиночные слова).

## 5. Поэтапный план реализации

## Этап 0. Проектирование и технический baseline

### Цели
- Зафиксировать архитектуру и API контрактов.
- Подготовить инфраструктуру разработки и качества.

### Задачи
1. Определить стек для desktop-приложения и Python-бэкенда.
2. Зафиксировать интерфейсы:
   - `STTProvider`,
   - `TTSProvider`,
   - `LLMProvider`,
   - `ProgressRepository`,
   - `LessonEngine`.
3. Определить форматы данных (Pydantic-схемы).
4. Настроить quality gates:
   - ruff/flake8,
   - mypy,
   - pytest.
5. Подготовить схему БД для прогресса и контента.

### Результат этапа
- Проектный каркас, CI-проверки, согласованная архитектурная схема.

---

## Этап 1. Базовая аудио-функциональность (TTS/STT MVP)

### Цели
- Получить стабильный цикл: текст -> озвучка, речь -> текст.

### Задачи
1. Реализовать TTS-адаптер с выбором:
   - языка,
   - голоса,
   - скорости.
2. Реализовать STT-адаптер:
   - запись с микрофона,
   - распознавание,
   - confidence score.
3. Добавить UI-контролы:
   - Play/Pause/Repeat/Record/Stop.
4. Ввести диагностику аудиоустройств.

### Результат этапа
- Рабочее аудио-ядро для дальнейшей учебной логики.

---

## Этап 2. Учеба с нуля: алфавит и произношение

### Цели
- Обеспечить обучение для пользователя без стартовых знаний.

### Задачи
1. Создать курс Pre-A0:
   - буквы и их звучание,
   - частые буквосочетания,
   - минимальные пары звуков.
2. Упражнения:
   - “слушай и повторяй”,
   - “распознай звук/букву”,
   - “прочитай вслух и сравни”.
3. Реализовать базовую оценку произношения:
   - похожесть по словам,
   - ошибки по ключевым звукам.
4. Ввести адаптивный повтор сложных букв/звуков.

### Результат этапа
- Полноценный стартовый трек с нуля до простого чтения и произношения.

---

## Этап 3. Диалоговый ИИ-модуль по темам

### Цели
- Перейти от одиночных упражнений к мини-диалогам.

### Задачи
1. Реализовать `DialogOrchestrator`.
2. Настроить Prompt Builder:
   - роль ИИ: учебный собеседник,
   - уровень сложности,
   - тема и цель сессии,
   - ограничения на длину реплик.
3. Жестко зафиксировать JSON-формат ответа ИИ:
   - `assistant_reply`,
   - `corrections`,
   - `new_vocabulary`,
   - `next_action`.
4. Добавить валидацию и fallback-обработку.
5. Подключить озвучивание ответа ИИ (TTS).

### Результат этапа
- Управляемые мини-диалоги “ученик <-> ИИ” в рамках заданной темы.

---

## Этап 4. Сценарии для путешествий (ядро практической ценности)

### Цели
- Достичь целевого “travel-ready minimum”.

### Задачи
1. Подготовить тематические сценарии:
   - аэропорт,
   - отель,
   - ресторан,
   - магазин,
   - больница/аптека,
   - полиция/экстренные случаи.
2. Для каждой темы сделать:
   - словарь активного минимума,
   - обязательные фразы-шаблоны,
   - 3-5 уровней вариаций диалога.
3. Ввести “режим стресс-ситуации”:
   - более быстрая речь,
   - неожиданные уточняющие вопросы.
4. Реализовать “карточку выживания”:
   - список критически важных фраз для быстрой тренировки.

### Результат этапа
- Пользователь может отрабатывать реальные путешественные сценарии.

---

## Этап 5. Оценка произношения и качество речи

### Цели
- Улучшить четкость и уверенность устной речи.

### Задачи
1. Ввести многокомпонентную оценку:
   - intelligibility (понятность),
   - phoneme/word accuracy,
   - fluency (темп, паузы).
2. Разработать фидбек:
   - что именно произнесено нечетко,
   - как исправить артикуляцию,
   - целевой образец (аудио + текст).
3. Добавить тренажер shadowing:
   - пользователь повторяет за эталоном в заданном ритме.
4. Реализовать сравнение прогресса “до/после” по трудным фразам.

### Результат этапа
- Объективный трек качества произношения и практический рост понятности.

---

## Этап 6. Система прогресса и персонализация

### Цели
- Сделать обучение управляемым и измеримым.

### Задачи
1. Ввести профиль компетенций:
   - лексика,
   - понимание,
   - произношение,
   - диалоговая реакция по темам.
2. Реализовать KPI:
   - completion rate,
   - retention rate,
   - pronunciation score,
   - scenario readiness score.
3. Сформировать персональный план повторений (SRS + слабые места).
4. Визуализировать прогресс:
   - дашборд по темам,
   - “готовность к поездке” в процентах.

### Результат этапа
- Пользователь видит понятный прогресс и приоритеты для улучшения.

---

## Этап 7. Расширяемость и новые направления

### Цели
- Подготовить систему для добавления неучтенных функций.

### Задачи
1. Ввести plugin-like расширения:
   - новые типы упражнений,
   - новые сценарии,
   - новые движки STT/TTS/LLM.
2. Реализовать feature flags:
   - безопасный запуск новых функций без регрессии.
3. Добавить конфигурируемые учебные траектории:
   - travel,
   - business,
   - exam prep.
4. Обеспечить возможность многопользовательского режима (на будущее).
5. Подготовить API-контракты для интеграции с внешними сервисами.

### Результат этапа
- Архитектура позволяет масштабировать продукт без переписывания ядра.

---

## 6. Нефункциональные требования

1. **Производительность**
   - минимальная задержка между репликами,
   - отзывчивость UI на стационарном ПК.
2. **Надежность**
   - корректная обработка ошибок сети/устройств,
   - fallback-сценарии.
3. **Безопасность**
   - хранение ключей в env/secure storage,
   - защита пользовательских данных.
4. **Качество кода**
   - type hints, линтинг, статический анализ, тесты.
5. **Тестируемость**
   - unit + integration + e2e-потоки критичных сценариев.

## 8. Метрики успеха проекта

1. Пользователь с нуля проходит Pre-A0 и A0 без ручного сопровождения.
2. Доля успешно завершенных travel-сценариев растет по сессиям.
3. Средний pronunciation score демонстрирует положительную динамику.
4. Пользователь может провести базовый диалог в критических сценариях:
   - аэропорт,
   - ресторан,
   - больница,
   - полиция,
   - магазин.
5. Система позволяет подключить нового провайдера STT/TTS/LLM
   без изменений учебной бизнес-логики.

---

## 9. Риски и меры снижения

1. **Низкое качество распознавания шумной речи**
   - шумоподавление, калибровка микрофона, retry.
2. **Нестабильные/неструктурированные ответы ИИ**
   - строгая JSON-схема + валидация + fallback.
3. **Перегрузка обучаемого сложным контентом**
   - ограничение когнитивной нагрузки, адаптивная сложность.
4. **Переоценка уровня готовности**
   - сценарные контрольные с независимыми критериями.
5. **Зависимость от внешних API**
   - абстракции провайдеров и резервные варианты.

## 10. Дорожная карта внедрения (практический порядок)

1. Этап 0 -> Этап 1 (техническое ядро).
2. Этап 2 (обучение с нуля).
3. Этап 3 (ИИ-диалоги).
4. Этап 4 (travel-сценарии и активный минимум).
5. Этап 5 (качество произношения).
6. Этап 6 (аналитика и персонализация).
7. Этап 7 (расширяемость и новые направления).

Каждый этап завершается:
- демонстрацией работоспособного инкремента,
- набором тестов,
- метриками качества,
- обновлением документации.

---

## 11. Рекомендованный итог MVP+

Минимально ценный релиз (MVP+) должен включать:
1. TTS/STT рабочий цикл на desktop.
2. Курс с нуля (буквы, звуки, базовые сочетания).
3. Мини-диалоги с ИИ по 3 ключевым темам:
   - аэропорт,
   - ресторан,
   - магазин.
4. Базовую оценку произношения и понятный фидбек.
5. Учет прогресса и адаптивное повторение.

После достижения MVP+ проект расширяется по этапам 4-7
до полной travel-ready платформы.
