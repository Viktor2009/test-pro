# Полный поэтапный план реализации модуля изучения иностранного языка

## 1. Цель и контекст

### 1.1. Цель проекта
Создать программный модуль для стационарного компьютера, который:
- озвучивает учебный текст (TTS),
- распознает речь обучаемого (STT),
- ведет тематические учебные мини-диалоги с ИИ,
- дает корректную и понятную обратную связь по ошибкам,
- отслеживает прогресс обучения,
- доводит обучаемого с нулевого уровня (включая алфавит и базовое
  произношение) до практического уровня для путешествий.

### 1.2. Практический результат обучения (target outcome)
Обучаемый должен уверенно решать базовые задачи за границей:
- аэропорт (регистрация, паспортный контроль, багаж),
- транспорт и навигация,
- заселение в отель,
- ресторан и кафе,
- магазин и покупки,
- аптека и больница,
- экстренные ситуации и полицейский участок,
- краткое бытовое общение.

### 1.3. Основные приоритеты
1. Качество произношения и восприятия речи.
2. Реальные диалоговые сценарии, а не только теория.
3. Удобство для пользователя с нулевым уровнем.
4. Измеримый прогресс и персонализация.
5. Расширяемая архитектура для будущих функций.

---

## 2. Принципы проектирования модуля

1. **Modular by design**: каждый компонент изолирован интерфейсом
   (STT, TTS, LLM, аналитика, контент, прогресс).
2. **Provider-agnostic**: возможность заменить провайдера STT/TTS/LLM
   без переписывания бизнес-логики.
3. **Structured AI output**: ответы ИИ в валидабельном JSON.
4. **Offline/Online strategy**: гибридная модель (лучшее качество при
   наличии сети, безопасный fallback при ее отсутствии).
5. **Pedagogy-first**: учебные сценарии управляют ИИ, а не наоборот.
6. **Observability**: логирование, метрики качества, контроль регрессий.
7. **Incremental delivery**: поэтапный выпуск, где каждый этап
   приносит работоспособную ценность.

## 3. Общая архитектура

### 3.1. Компоненты
1. **Desktop UI Layer** (реализация — **этап 8** плана; до него проверка через CLI)
   - экран урока, запись/воспроизведение, подсветка ошибок,
     прогресс-дашборд;
   - **диалог с ИИ** (лента реплик), **текущий уровень**, **прогресс**;
   - текстовый режим: отображение реплик и заданий; **поле ввода текста** при
     необходимости набрать ответ;
   - **постепенная доводка** после первого релиза UI: сохранение прогресса на диск,
     выбор провайдеров, аудио-цикл в уроке, travel/траектории в диалоге,
     честные метрики попыток (см. **раздел 12**).
2. **Audio I/O Layer**
   - захват микрофона, воспроизведение аудио, базовая обработка сигнала.
3. **Speech Layer**
   - STT Adapter: аудио -> текст (+ confidence),
   - TTS Adapter: текст -> озвучка.
4. **AI Dialogue Layer**
   - LLM Gateway,
   - Prompt Builder,
   - Conversation Memory.
5. **Learning Engine**
   - генерация упражнений,
   - оценка ответов,
   - адаптация сложности,
   - план повторений (SRS).
6. **Pronunciation Assessment**
   - оценка произношения по сегментам (слово/звук),
   - рекомендации по коррекции.
7. **Progress & Analytics**
   - журнал попыток, KPI, отчеты по темам и навыкам.
8. **Content Management**
   - словарь, фразы, сценарии, уровни, тематические блоки.

### 3.2. Ключевые потоки
1. TTS-поток: текст урока/реплики ИИ -> аудио.
2. STT-поток: голос пользователя -> транскрипт.
3. Диалоговый поток: реплика пользователя -> ИИ-ответ + фидбек.
4. Оценочный поток: ответ -> анализ ошибок -> обновление прогресса.
5. Адаптивный поток: прогресс -> персонализированное следующее задание.

## 4. Педагогическая модель обучения

### 4.1. Уровни
1. **Pre-A0 (с нуля):**
   - алфавит, буквы, звуки, диграфы/сочетания,
   - базовые правила чтения,
   - первичное фонетическое различение.
2. **A0/A1 (базовый выживания):**
   - приветствия, числа, время, простые вопросы/ответы,
   - шаблонные фразы по бытовым ситуациям.
3. **A1+ Travel Ready Minimum:**
   - готовые фразовые блоки для путешествий,
   - короткие диалоги в критически важных сценариях.

### 4.2. Навыки
- Listening (восприятие речи),
- Speaking (произношение + реакция),
- Functional vocabulary (активный минимум),
- Scenario communication (коммуникация по ситуации).

### 4.3. Подходы
1. Comprehensible Input (понятный вход).
2. Active Recall (активное воспроизведение).
3. Spaced Repetition (интервальные повторения).
4. Shadowing (повтор за диктором).
5. Chunk-based learning (фразовые блоки, а не одиночные слова).

## Этап 8. Графический интерфейс (Desktop UI)

### Цели
- Дать обучаемому наглядное представление о **ходе диалога с ИИ**,
  **текущем уровне**, **прогрессе** и снять необходимость работать только из CLI.

### Задачи
1. **Диалог с ИИ**
   - лента реплик (пользователь / ассистент), понятное разделение ролей;
   - синхронизация с тем же контрактом, что использует `DialogOrchestrator` /
     travel-сессии (текст ответа ИИ, коррекции, подсказки — по мере готовности
     бэкенда).
2. **Текущий уровень**
   - отображение уровня/трека из профиля обучения (`level_hint`, целевой язык,
     при необходимости — визуальная шкала или подпись сценария).
3. **Прогресс**
   - панель или экран прогресса: KPI, компетенции, «готовность к поездке» и
     связанные метрики из слоя Progress & Analytics (см. этап 6);
   - при необходимости — краткая сводка за сессию / за неделю.
4. **Текстовый режим обучения**
   - если взаимодействие идёт **текстом** — весь релевантный текст (реплики ИИ,
     задания, пояснения) отображается в интерфейсе читабельно (область сообщений,
     карточки упражнений и т.п.).
5. **Ввод текста**
   - при заданиях «напечатать ответ» — **явное поле / окно ввода текста**
     с подтверждением отправки (Enter / кнопка), валидация пустого ввода по UX-
     правилам продукта.
6. **Интеграция с ядром**
   - тонкий UI-слой поверх пакета `lang_learn`: без дублирования бизнес-логики;
   - выбор стека UI (например PySide6/Qt, Flet и др.) — отдельное решение в рамках
     этого этапа, согласованное с `docs/stage0_technical_baseline.md`.
7. **Голос и аудио (после текстового контура, по приоритету)**
   - кнопки записи/воспроизведения, индикация устройств — как расширение уже
     реализованного аудио-слоя (этап 1).
8. **Персистентность прогресса в GUI**
   - подключить к окну тот же контракт `ProgressRepository`, что и в ядре
     (например `SqliteProgressRepository`), путь к БД в профиле пользователя
     или настраиваемый каталог данных;
   - инициализация схемы из `db/schema.sql`, корректное закрытие соединения при
     выходе из приложения.
9. **Выбор провайдеров в интерфейсе**
   - выбор зарегистрированного LLM (не только `stub`) и сохранение выбора
     в сессии/конфиге;
   - при установленном extra `audio` — опциональный выбор TTS/STT и
     индикация недоступности провайдера.
10. **Аудио в уроке и согласование с педагогикой**
    - для шагов «слушай и повтори» / произношение: запись с микрофона, STT,
      подстановка транскрипта или сравнение с эталоном;
    - воспроизведение эталона через общий слой воспроизведения WAV (где
      применимо), не только через pyttsx3 по фрагментам текста.
11. **Travel-сценарии и траектории в UI**
    - отдельный режим или вкладка «сценарий путешествия» поверх
      `TravelScenarioService`;
    - связка выбора траектории в параметрах сессии с контекстом диалога
      (`build_dialog_context` / расширение `DialogSessionContext`), а не только
      информативный combobox.
12. **Оценка попыток диалога в GUI**
    - убрать заглушки вроде фиксированного балла; использовать поля
      structured JSON, эвристики произношения/лексики или явные флаги
      «успех/частично» для KPI и компетенций.
13. **Наблюдаемость и диагностика в GUI**
    - логирование ошибок LLM/сети/аудио (без секретов и ПДн), опционально
      окно «последняя ошибка» для разработки.
14. **Качество кода UI со статическим анализом**
    - довести пакет GUI до прохождения mypy (stubs для tkinter, узкие
      `# type: ignore`, выделение логики без tkinter в тестируемые функции).

### Результат этапа
- Рабочий графический клиент на стационарном ПК, в котором обучаемый видит
  диалог, уровень, прогресс и может вводить текстовые ответы там, где это
  требуется сценариом;
- по мере выполнения пунктов 8–14 — пользовательский продукт с сохранением
  прогресса, голосовым контуром и сценариями без обязательного CLI.

**Статус (часть 1):** см. `docs/stage8_gui.md` — окно на **tkinter**, команда
`python -m lang_learn gui`: диалог с ИИ, поля уровня/языка/темы, панель прогресса,
ввод текста (Enter / кнопка), вкладка урока Pre-A0. Дальнейшие инкременты —
по **разделу 12** и пунктам 8–14 этапа 8.

## 6. Нефункциональные требования

1. **Производительность**
   - минимальная задержка между репликами,
   - отзывчивость UI на стационарном ПК.
2. **Надежность**
   - корректная обработка ошибок сети/устройств,
   - fallback-сценарии.
3. **Безопасность**
   - хранение ключей в env/secure storage,
   - защита пользовательских данных.
4. **Качество кода**
   - type hints, линтинг, статический анализ, тесты.
5. **Тестируемость**
   - unit + integration + e2e-потоки критичных сценариев.

## 8. Метрики успеха проекта

1. Пользователь с нуля проходит Pre-A0 и A0 без ручного сопровождения.
2. Доля успешно завершенных travel-сценариев растет по сессиям.
3. Средний pronunciation score демонстрирует положительную динамику.
4. Пользователь может провести базовый диалог в критических сценариях:
   - аэропорт,
   - ресторан,
   - больница,
   - полиция,
   - магазин.
5. Система позволяет подключить нового провайдера STT/TTS/LLM
   без изменений учебной бизнес-логики.

## 9. Риски и меры снижения

1. **Низкое качество распознавания шумной речи**
   - шумоподавление, калибровка микрофона, retry.
2. **Нестабильные/неструктурированные ответы ИИ**
   - строгая JSON-схема + валидация + fallback.
3. **Перегрузка обучаемого сложным контентом**
   - ограничение когнитивной нагрузки, адаптивная сложность.
4. **Переоценка уровня готовности**
   - сценарные контрольные с независимыми критериями.
5. **Зависимость от внешних API**
   - абстракции провайдеров и резервные варианты.

## 11. Рекомендованный итог MVP+

Минимально ценный релиз (MVP+) должен включать:
1. TTS/STT рабочий цикл на desktop.
2. Курс с нуля (буквы, звуки, базовые сочетания).
3. Мини-диалоги с ИИ по 3 ключевым темам:
   - аэропорт,
   - ресторан,
   - магазин.
4. Базовую оценку произношения и понятный фидбек.
5. Учет прогресса и адаптивное повторение.
6. Для **пользовательского** релиза с GUI: сохранение прогресса между сеансами
   (SQLite или эквивалент) и минимальный голосовой контур в уроке/диалоге
   (запись + STT там, где сценарий требует устной речи).

Полноценный **графический интерфейс** (этап 8) может идти параллельно поздним
этапам или сразу после стабилизации диалога и прогресса; для MVP+ достаточно CLI,
для пользовательского продукта UI считается обязательным завершением этапа 8
и ключевых пунктов **раздела 12**.

После достижения MVP+ проект расширяется по этапам 4-8
до полной travel-ready платформы с удобным отображением сценариев и прогресса.

## 12. Бэклог: доработка GUI и связки с ядром (инкременты)

Ниже — упорядоченный список для **постепенной** реализации после «этап 8,
часть 1» (tkinter-окно, текст, Pre-A0, сводка прогресса в памяти). Порядок
можно уточнять по продуктовым приоритетам; логичная первая волна — персистентность
и выбор LLM, затем аудио и travel.

### Волна A — данные и провайдеры (основа для ежедневного использования)

1. **Прогресс на диске в GUI** — `SqliteProgressRepository` (или абстракция с
   тем же контрактом), путь к файлу БД, миграция/DDL при старте, закрытие при
   выходе.
2. **Идентификатор пользователя** — поле или настройка `user_id` (пока
   локально), чтобы не смешивать попытки на одной машине при желании.
3. **Выбор LLM в UI** — combobox/настройка из `ProviderRegistry`, не хардкод
   `stub`; сообщение пользователю при ошибке провайдера.
4. **Опционально: TTS/STT в UI** — при `pip install -e ".[audio]"` — выбор
   провайдера и понятные сообщения при отсутствии зависимостей.

### Волна B — аудио и педагогическое соответствие упражнениям

5. **Запись и распознавание в уроке Pre-A0** — кнопки «Записать» / «Стоп»,
   вызов STT, заполнение поля ответа или отдельная ветка проверки по
   транскрипту.
6. **Воспроизведение эталона** — единый путь с `audio_io.playback` для WAV,
   где эталон уже синтезируется как аудио; сохранение согласованности с
   упражнениями «слушай–повтори».
7. **Диалог: голос пользователя** — опциональный режим «ответ голосом» с STT
   и отображением распознанного текста в ленте перед отправкой в оркестратор.

### Волна C — сценарии путешествий и контекст диалога

8. **Режим travel в GUI** — выбор сценария из `TravelScenarioService`, старт
   диалога с контекстом сценария (stress/variation из этапа 4).
9. **Траектория → промпт** — выбранная траектория влияет на `DialogSessionContext`
   или на системный промпт (не только метка в `details` попытки).

### Волна D — метрики, UX и качество кода

10. **Честный `score` и `details` для диалога** — расчёт из ответа ИИ и/или
    локальных эвристик; согласование с KPI этапа 6.
11. **TTS ответа ассистента в чате** — опционально, через `DialogOrchestrator`
    с провайдером TTS (уже предусмотрено в ядре).
12. **Улучшение UX** — масштаб шрифта, светлая/тёмная тема из настроек,
    длинные тексты, фокус и доступность (клавиатура).
13. **mypy для модулей `gui/`** — stubs или минимальные правки типов,
    чтобы `mypy src/lang_learn` не игнорировал GUI-слой.

Завершение каждой волны: обновление `docs/stage8_gui.md`, тесты на логику без
tkinter где возможно, ручная проверка сценария на Windows.
